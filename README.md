# EroTorrent → Hydra Launcher source

Скрипт собирает раздачи с `erotorrent.org` и генерирует **erotorrent.json** — источник загрузок для [Hydra Launcher](https://github.com/hydralauncher/hydra) (формат: `{ name, downloads: [{ title, uris, uploadDate, fileSize }] }`).

## Чем этот сайт отличается от обычных торрент-трекеров

На erotorrent.org раздача может быть оформлена **двумя способами**:

1. **`.torrent`-файл** — скачивается с сайта (`index.php?do=download&id=N`), из него вычисляется infohash v1 и строится magnet-ссылка.
2. **Облако** — внешняя ссылка на архив/папку (pixeldrain, Google Drive, mega.nz, workupload и др.).

Hydra поддерживает не все хостеры — только те, что перечислены в `getDownloadersForUri` его исходников (gofile, pixeldrain `/u/<id>`, datanodes, mediafire, fuckingfast, vikingfile, rootz, archive.org + magnet). Поэтому скрипт:

- **magnet** строит из `.torrent` (как в торрент-трекерах);
- **pixeldrain `/u/<id>`** кладёт в `uris` как есть — Hydra качает напрямую;
- **Google Drive / mega.nz / workupload и прочее** пропускает с предупреждением в логе: Hydra отбрасывает ссылку, а если она попадёт в `uris` — отфильтрует весь релиз целиком.

У одной игры может быть и облако, и торрент — тогда в `uris` обе ссылки, и Hydra предложит выбор загрузчика.

## Файлы

| Файл | Назначение |
|---|---|
| `scrape.mjs` | скрапер: обходит страницы сайта, собирает торренты и облака, пишет `erotorrent.json` |
| `erotorrent.json` | итоговый источник для Hydra |
| `.cache/downloads.json` | кэш «страница игры → ссылки»: повторные запуски не качают торренты заново |
| `.github/workflows/update.yml` | автозапуск по расписанию + коммит обновлённого JSON |

## Запуск

```bash
node scrape.mjs --pages 3          # последние 3 страницы новостей (~90 игр, по умолчанию)
node scrape.mjs --pages 10         # 10 страниц новостей
node scrape.mjs --full             # перечитать кэшированные из news-обхода и обновить метаданные
node scrape.mjs --all              # ВЕСЬ сайт через sitemap (~5150 игр, см. ниже)
node scrape.mjs --all --limit 1000 # первые 1000 новых игр из sitemap (порциями)
node scrape.mjs --check-updates --updates-limit 1000 --refresh  # проверка обновлений
```

### Покрытие сайта

| Режим | Что парсит | Время |
|---|---|---|
| по умолчанию (`--pages 3`) | только новости: ~3 последние страницы | минуты |
| `--pages N` | N страниц новостей | N × ~2,5 сек × игры |
| `--all` | весь каталог: ~5150 страниц игр из sitemap | **несколько часов** (паузы вежливости) |
| `--all --limit N` | до N **новых** игр за запуск | ~1 ч на 1500 |
| `--check-updates --updates-limit N --refresh` | проверяет N закэшированных игр на обновление версии | ~1 ч на 1500 |

`--all` идёт по sitemap'у (`news_pages.xml`), кэш сохраняется каждые 50 игр, так что процесс можно прерывать и продолжать. Порядок обхода — как в sitemap (от новых к старым), поэтому даже частичный прогон сначала наполняет каталог свежим.

**Режим `--check-updates`** решает проблему устаревших ссылок: у каждой игры в кэше хранится отпечаток «размер + дата обновления + версия + название + тип раздачи». Если на сайте вышла новая версия (изменился размер/версия/тип), скрипт замечает это, перекачивает `.torrent`/облако и перезаписывает `uris`. `--refresh` разрешает перекачку, без него изменения только фиксируются в метаданных. В Actions запускается ежедневно по 1500 игр — полный круг по каталогу примерно раз в 3,5 недели.

**Для сервера/GitHub Actions:** полный `--all` укладывается в лимит Actions (6 ч на job) порциями по 1500 — каталог ~5150 игр наберётся за 3–4 дня.

Требуется Node.js 18+. Скорость ограничена паузами (`PAGE_DELAY_MS` / `TORRENT_DELAY_MS` в начале `scrape.mjs`), чтобы не нагружать сайт.

## Как подключить в Hydra

Вариант А — через GitHub (рекомендуется):

1. Создайте репозиторий и запушьте эти файлы.
2. Включите GitHub Actions (вкладка Actions → включить workflows) — JSON будет обновляться сам по расписанию.
3. Ссылка на источник: `https://raw.githubusercontent.com/<user>/<repo>/main/erotorrent.json`
4. Hydra → **Настройки → Источники загрузки → +** → вставить ссылку.

Вариант Б — локально: держите `erotorrent.json` на диске и обновляйте скриптом, но в актуальной версии Hydra добавить источник можно только по публичной URL-ссылке.

## Как работает автообновление

`update.yml` запускается по cron (каждый день в 03:00 и 05:00 UTC) и по кнопке (workflow_dispatch). После каждой фазы скрапа результаты сразу публикуются скриптом `publish.sh` (коммит + пуш с защитой от гонок: если remote ушёл вперёд — rebase и повтор до 6 раз; при конфликте данных побеждает свежий скрап).

1. `node scrape.mjs --pages 5` + публикация — новинки
2. `node scrape.mjs --all --limit 1500` + публикация — порция каталога
3. `node scrape.mjs --check-updates --updates-limit 1500 --refresh` + публикация — проверка версий
4. Ссылка `raw.githubusercontent.com/.../erotorrent.json` всегда отдаёт свежую версию; Hydra подтянет её через «Синхронизировать» в настройках источников.

Публикация порциями означает: даже если job упадёт посередине или его обгонит другой запуск, уже собранные игры не пропадут.

## Заметки

- Игры без блока релиза (анонсы, скрытые/удалённые страницы — сайт отдаёт 403) пропускаются; это норма, не баг.
- Страница у игры может содержать несколько версий релиза; парсится самая свежая (последний блок).
- Версия релиза (например `v1.1.8`) участвует в отпечатке обновлений, но в итоговый JSON не пишется — Hydra ожидает только `title/uris/uploadDate/fileSize`.
- Сопоставление в Hydra идёт по названию (`title`), чистота заголовка важнее.
- Облака, которые Hydra не поддерживает, пропускаются; расширить список можно в `SUPPORTED_CLOUD_HOSTS` (но сначала убедитесь, что Hydra умеет хостер — см. `getDownloadersForUri` в его исходниках).
